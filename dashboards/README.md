# Grafana dashboards

Seven dashboards. **Open "Start Here" first** — if its four boxes are green,
everything is fine and you're done.

| Dashboard | Question it answers | When to open it |
|---|---|---|
| **Start Here — Is Anything Broken?** | Is anything wrong right now? | Always first. |
| **Services** | How is one service doing? | Start Here named something broken. Pick its *Area* and *Service* at the top. |
| **Machines** | How is one machine doing? | Things are slow, or a disk/memory dial is orange or red. |
| **PantryBot** | Is PantryBot working, and is anyone using it? | Anything PantryBot. |
| **Minecraft** | Is the Minecraft server healthy? | Lag, crashes, or player complaints. |
| **Logs** | What exactly did an app say? | You need the actual error text. |
| **Sites & Failover** | Which site (home / Oracle / Canada) is each thing running at? | Failover work, or "is it running somewhere else?" |

Every dashboard has the same row of links across the top, so you can jump
between them without going back to the list.

### Reading them

- **Green** is fine. **Orange** is getting tight. **Red** needs attention.
- Hover the small **ⓘ** beside any panel title for what it means and what a bad
  value looks like.
- "**Nothing here — good.**" on a table means there is nothing broken to list.
- "**no data**" or "**database unreachable**" means the thing being measured is
  itself down — that *is* the problem, not a broken dashboard.

### Typical path when something is wrong

1. **Start Here** — a red box, and the table under it names the app.
2. **Services** — pick that app. *Restarts today* and *Why it last stopped* say
   what kind of failure it is (`OOMKilled` = ran out of memory).
3. Scroll to **Latest log lines** at the bottom of Services — the reason is
   almost always in the last few lines before a restart.

## For maintainers

**Source of truth is this directory.** Four dashboards are generated; three are
hand-written.

| File | How it is made |
|---|---|
| `start-here.json`, `services.json`, `machines.json`, `pantry-bot.json` | Generated by `scripts/gen-dashboards.py` — edit the script, not the JSON. |
| `logs.json`, `minecraft.json`, `site-service-health.json` | Hand-written. Edit directly. |

After any change:

```bash
python3 scripts/gen-dashboards.py           # regenerate the generated four
python3 scripts/gen-dashboards-configmap.py # rebuild dashboards-configmap.yaml
bash scripts/validate-grafana-dashboards.sh # byte-checks the ConfigMap copy
```

Deploy with the manual **Deploy Grafana** workflow
(`.github/workflows/grafana-deploy.yml`). Nothing reaches Grafana until it is
dispatched.

**Deleting a dashboard file deletes the dashboard.** The provisioning provider
has `disableDeletion: false`, so removing a JSON file here removes it from
Grafana on the next deploy. That is deliberate — with it set to `true`, retired
dashboards stayed in Grafana indefinitely after their files were gone.

**Design rules the generated dashboards follow**, worth keeping if you add to them:

- **Pickers read live data.** The Services list is built from kube-state-metrics
  at view time, so a new Deployment appears without editing anything. Only
  workloads meant to be running (1+ replicas) are listed.
- **One dashboard, two machine types.** Every Machines panel carries a Linux
  query (`node_exporter`) *and* a Windows query (`windows_exporter`); only the one
  matching the picked machine returns data.
- **Never hard-code a name that does not exist yet.** A panel pointed at a
  missing job or metric shows "No data", which looks identical to a broken query.
  Count what exists instead (Sites & Failover counts `site="canada"` targets
  rather than probing a job name).
- **Escape regexes for RE2, not Python.** Prometheus and Loki use Go's RE2, which
  rejects `\-`. Python's `re.escape` emits exactly that.
- **Pod selector** `pod=~"<name>-([a-z0-9]+-)?[a-z0-9]+"` allows at most two
  suffix segments, so `cartwise` does not also match `cartwise-db`'s pods.

**Known gaps** (the dashboards report these honestly rather than hiding them):

- `minecraft_world_size_bytes` never registers — exporter bug, #374.
- Fencing-lease holder not scraped — Prometheus config drift, #373.
- Canada has no scrape target — #375.
- chasebot has no hardware exporter scraped, so it is absent from Machines — #372.

The full history of the 2026-09-21 audit — every broken panel, why, and what was
retired — is in git history for this file and in issues #371–#376.
